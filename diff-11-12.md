# Pong: from `pong-11` to `pong-12` — "The Resize Update"

## 1. General task description

Since `pong-1` the window has been `resizable = true`, but `push` was never told when the window size changes. After resizing, the game picture can end up the wrong size or in the wrong place.

In `pong-12` we fix this with one small function: when LÖVE reports a resize, we pass the new size to `push`, which re-calculates the scaling so the 432×243 virtual screen always fits the window correctly.

### Files

| File | What happens |
|---|---|
| `main.lua` | Edited — one new function |
| `sounds/*.wav` | Ready-made assets; the repo ships slightly different copies of the same three files in `pong-12` — just copy them from `pong-12`, nothing to write |

| `class.lua`, `push.lua`, `font.ttf` | Third-party, unchanged |

## 2. Steps from `pong-11` to `pong-12`

### Step 1. (Optional) Refresh the sound files

Replace the files in `sounds/` with the ones from `pong-12`. The names and how they're used don't change.

### Step 2. Update the header comment

```lua
    pong-12
    "The Resize Update"
```

### Step 3. Handle window resizing

Add a new function after `love.load()` (before `love.update`):

```lua
function love.resize(w, h)
    push.resize(w, h)
end
```

> `love.resize(w, h)` is a LÖVE **callback**, like `love.load` or `love.keypressed`: LÖVE calls it automatically whenever the window changes size, passing the new width and height. We simply forward them to `push`.

### Step 4. Run and check

Run `love .`. Drag the window edge to make it bigger, smaller, wider or taller (or maximize it). The game stays properly scaled and centered, with black bars if the window's shape doesn't match 16:9.
